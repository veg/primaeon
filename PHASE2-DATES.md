# Phase 2 — dates: the date layer and the `/time` review page

PLAN-TEMPORAL.md phase 2. Two repositories, two branches, nothing pushed and no pull request
opened. This document records what landed and what the verification measured; it is not a plan.

**Status: partly done.** The code is written, every commanded suite is green, and the page has been
driven in a browser against real dated files. Three things stand between this and merge, and they
are in §4 before anything else: the branch does not merge with `main`, nothing is ever saved to
IndexedDB, and the units inference can turn "no dates" into confident wrong dates behind a green
gate.

---

## 1. What a reader can now do

Drop an alignment — with or without a metadata table, an Auspice build, a JSON map, a custom
pattern or nothing at all — onto `/time/`, and see one row per sequence saying what date was read,
which of the three upstream parsers read it, which characters it read, and which half of the answer
was invented rather than found. Where the upload also carries a tree with real branch lengths, the
same page fits root-to-tip divergence against those dates and says whether they carry a clock signal
at all, and it does both without loading a model, a graph or a byte of ONNX.

## 3. The date contract

Three upstream dispatchers read dates, and they disagree about almost everything. The library ports
the four *parsers* verbatim; the runtime layer makes one decision per disagreement, records which it
made, and never makes it silently.

### The parsers, and the rule that wins

| Source of the date | Reference | Rule ids |
|---|---|---|
| A cell in a metadata table | `temporal.parse_date_to_decimal` | `numeric`, `decimal_year`, `ymd`, `non_calendar_numeric`, `non_calendar_embedded`, `out_of_range`, `unparsed` |
| A sequence name, built-in patterns | `temporal.extract_date_from_string` | `header_iso`, `header_decimal_year`, `header_year_month`, `header_trailing_year`, `header_unit_token`, `header_unit_suffix`, `header_bare_number` |
| A sequence name, HIV/LANL conventions | `dating.parse_header_timestamp` | `archival_1959`, `korber_isolate`, `lanl_pipe_year`, `wpi`, `dpi` |
| An Auspice attribute or a JSON map value | `dating._parse_timestamp_flexible` | `flexible_numeric`, and the calendar rules |

**Precedence, highest first, one winner per taxon:**

1. **A pre-parsed map** (`{name: date}` JSON, an Auspice build's tip attributes).
2. **A metadata table cell**, when the taxon matched a row.
3. **A custom pattern**, which runs *before* the built-in name rules — this is `dating.py`'s
   `--date-regex` position.
4. **The built-in name rules**, `dating`'s HIV conventions first, then `temporal`'s patterns.
5. **Nothing** — the row survives as undated, carrying `out_of_range` (a date was read and the
   1800–2100 gate rejected it), `unparsed` (no rule matched) or `none`.

**Where the three dispatchers disagree, and what this layer does:**

| Disagreement | `temporal.py` | `dating.py` | Here |
|---|---|---|---|
| Delimiter | pandas sniffs (`sep=None`) | decided by file extension | Sniffed from content; the extension is a *hint* (`delimiter_extension_hint`, `agrees`), `DATES_DELIMITER_GUESSED` raised |
| Column names | `(strain, time)` | `(id, time)` | Both ladders, `temporal`'s first; the rung that answered is in `strain_col_source` / `date_col_source` |
| No date column found | produces no dates at all | guesses `columns[1]` | Guesses, flags at warn, and refuses to let the date column *be* the strain column — which neither reference checks |
| Cell dtype | inferred (so `402124` → `'402124.0'`) | `dtype=str` | pandas-faithful, and the damage is *counted* as `table.numeric_names` so `DATES_TABLE_NO_MATCH` names the real cause |
| Header fallback | only when the table dated **nothing** (`temporal.py:323`) | per taxon (`dating.py:481-483`) | `dating`'s, as the default (`headerFallback: true`); `temporal`'s is the checkbox; `DATES_HEADER_FALLBACK` names the count either way |
| The 1959 anchor | absent | applied first, unconditionally | **Opt-in, default off**; offered with the exact rows it would move |
| A missing file | silently ignored | `FileNotFoundError` | Neither: `DATES_SOURCE_UNREADABLE`, returned not thrown |

`timeUnits` is the only calendar/non-calendar switch, and **the library never infers it**
(`js/src/dates.js:33-38`). The application does, from which path dates more, with a calendar
majority (`DATE_THRESHOLDS.calendarMajority = 0.5`) winning outright. See finding 1 in §4.

## 4. What the verification measured

### Red and thin, first

**(a) The branch does not merge with `main`, and no suite has run on a merged tree.**
`feat/time-page` was cut from `581a203`; `main` has since advanced 19 commits to `4166d35`.
`git merge-tree main HEAD` produces four conflicts: add/add in `web/src/lib/handoff.ts` and
`web/src/lib/handoff.test.ts`, content in `web/src/routes/+page.svelte` and
`web/src/routes/analyze/+page.svelte`. The handoff work is **duplicated**: the merge base has no
`handoff.ts`, and both `main` (PR #2) and this branch wrote one independently, to the same design
("memory first, `sessionStorage` only as a reload fallback"), differing by 54/69 lines. Someone must
choose which survives; the branch's 6 handoff tests are written against its own.

**(b) The review is never saved, on any dataset.** After ~2 s the page mints `/time/?id=<uuid>` into
the address bar, and the IndexedDB write that id addresses always fails:
`Failed to execute 'put' on 'IDBObjectStore': #<Object> could not be cloned`. Reproduced 5/5 on
three files; the `timesets` store exists and is empty after every run. Cause at
`web/src/routes/time/+page.svelte:293` — `saveTimeSet({ ...record, id: recordId })` is handed a
record built from Svelte 5 `$state`, so the graph still holds reactive Proxies and `structuredClone`
throws. Fix is `$state.snapshot(...)` before the put. Consequence: reload or share the URL the page
just wrote and you get an empty drop zone. The page *does* say "This review was not saved", but at
the very bottom of section 3, in raw browser-exception English, while the address bar says the
opposite. **No test covers persistence, which is why the e2e is 6/6 green.**

**(c) Units inference can turn "no dates" into confident wrong dates behind a green gate.**
`runtime/src/dates/ingest.js:282` decides the time axis by counting which path dates more. Measured
on a four-row table whose date column is US-format `12/25/2021`: the calendar path dates 0 (the
reference returns NaN for all four), the non-calendar path dates 4 via `temporal.py:96`'s
first-number-anywhere rule, so the run reads as **generations**, every sequence is dated to its month
number, `ok: true`, and `readyGate` passes. Driven in the browser on `H1N1_2009_pandemic.fasta`:
clicking "Generations" — an option the page's own inference line invites, by saying it dates 100
rather than 95 — gives 100 of 100 dated, span 1.00 to 46,241,654.00, values read off strain numbers
and clone ids, and the loudest sentence on the page reads *"These dates are ready to use."*
`DATES_MIXED_SCALE` fires with an excellent message and the clock preview says the signal is
negligible, but a warn-severity diagnostic is outranked by a green light. The cheap fixes:
let `DATES_MIXED_SCALE` block `ready` the way an undated set does, and make the inference line say
what the alternative would *cost*, not only how many it would date. Same control is safe on Smc6,
where generations still dates 0 of 20.

### Review findings

Twelve, from a senior read of both diffs: 1 high (finding (c) above), 3 medium-high, 4 medium,
4 low.

**Medium-high.**

1. **`runtime/src/clockRegression.js` is on the wrong side of the split.** Its own header says it
   mirrors `run_ols_dating` and the per-taxon record builder "formula by formula", and the formulas
   do match line for line. It knows about no file, no URL, no session and no message;
   `web/src/lib/time/clock.ts:5-7` says the giveaway out loud — "because `mcp/` and `server/` will
   want it verbatim the moment the dating tool lands". That is CLAUDE.md's own test for library code.
   The stated justification (it is the independent check for the phase-3 port) is an argument for a
   second implementation in the *engine's* test suite, not for shipping the estimator in the app
   permanently. Decide before phase 3 ports `run_ols_dating`, or the app carries two estimators
   nobody is allowed to reconcile. Same question, weaker, for `rootToTip.js`.
2. **Predicted dates are computed from a negative rate, where the reference refuses.**
   `clockRegression.js:181` reads `Math.abs(mu) > PREDICT_RATE_FLOOR`; `dating.py:3035` reads
   `if active_model['mu'] > 1e-6: … else: np.full(…, np.nan)`. Measured against the executed
   reference on a downward slope: Python returns all-NaN predictions, this returns finite predicted
   dates and finite temporal residuals for every row. `fit.ok` stays true under
   `NON_POSITIVE_RATE`, so `ClockPreview.svelte:162-196` will render a "Looks (years)" column derived
   from a downward slope — and the e2e's own H5N1 flow is exactly such a fit.
3. **A taxon that *was* matched to a metadata row prints "not in table".**
   `ingest.js:791-801` builds the dated row from the winning hit only, discarding
   `match.assignments`, so when a matched row's cell is unreadable and the header fallback rescues
   the taxon, the row carries `matched_name: null, match_tier: null`, and `ruleLabel.ts:120` renders
   that as "not in table". Measured. This is the exact class of misdirection the layer exists to
   remove: it sends the reader to fix the wrong thing.

**Medium.**

4. **The custom-pattern budget does not bound a single name, and its two warnings share a code that
   crashes the page.** `regex.js:149` checks the clock only when `out.scanned % 64 === 0`, so under
   64 taxa it fires once, at `scanned = 0`, and never again; in every case one catastrophically
   backtracking name runs to completion, on the main thread, because
   `web/src/routes/time/+page.svelte:23-25` runs the ingest synchronously. Separately,
   `ingest.js:666` and `:675` both push `DATE_REGEX_NO_MATCH` and both fire when a sweep stops before
   any match, while the page renders `{#each [...refusals, ...warnings] as w (w.code)}` — Svelte 5.57
   throws `each_key_duplicate` on a repeated key.
5. **The page's one error path is itself an error.** `+page.svelte:117-119` assigns `failure` inside
   the `$derived.by` at line 102; Svelte 5.57 throws `state_unsafe_mutation`. The one case this catch
   exists for — `ingestDates` throwing because the linked library predates `dates.js`, which is
   precisely the pinned `ENGINE_REF` situation — replaces the intended `data-state="failed"` refusal
   with an uncaught framework error.
6. **Undated taxa can be dropped with no warning at all.** `ingest.js:981` raises
   `DATES_PARTIAL_COVERAGE` only below `lowCoverageFraction` (0.9), so a run failing to date up to
   10 % emits nothing. Measured on the flagship: korber is 142/143 and CONSENSUS is absent from the
   warning list. `/time` is saved by its own gate and by `unmatched_taxa`, but the ingest is what
   `mcp/` and `server/` will mount, and there the warning list *is* the message.
7. **AI attribution is in the engine branch's git history**, against the house rule. Three of six
   commits on `feat/date-parsers` — `d998cab`, `24da906`, `490b11d` — end with `Co-Authored-By:

**Low.** `se_mu` omits `dating.py:1210`'s `max(1e-15, …)` floor (3.5e-18 vs 3.16e-8 on a
near-perfect fit); `r` returns NaN where `dating.py:1266` returns 0.0 on flat divergence; three line

### What the green result does not cover

The suites were run; the science was not audited. The remarkable numerical claims — the phylotree
reroot defect losing exactly 0.011, the 35.4 % rate deviation at 8.38 standard errors, korber
142/143, the 1959 anchor being inert on korber — are asserted by the new tests themselves, and a
test that pins a measured constant proves only that the code still produces it. One deserves a
reviewer's attention on its own terms: `runtime/test/clock-preview.test.js` **deliberately asserts
that the clock preview's rate deviates from truth by more than 3 of its own standard errors**. That
is honest testing of a known limitation, but it means `/time` prints a rate whose stated standard
error understates the real sampling error by roughly a factor of eight, and the page's copy is the
only thing stopping a reader from reading `se_mu` as an interval.

## 5. Upstream problems found and not fixed

For the engine's issue list. All are replicated in the port, per PLAN.md §5.3 rule 3, and every one
is surfaced rather than silently carried.

**`hyphaeon/temporal.py`**

1. **`:80` vs `:116` — the docstring is wrong about the commonest case.** It promises
   `parse_date_to_decimal('2021')` → 2021.5; `float()` claims the string first and the answer is
   2021.0, i.e. **1 January**. Pinned by the reference's own `tests/test_temporal.py:35`. A bare year
   anchored at 1 January is a *worse* silent error than mid-year, not a smaller one.
   **PLAN-TEMPORAL.md §2.1 repeats the docstring's claim and needs correcting.**
2. **`:132-142` — a missing month becomes June and a missing day the 15th**, and an out-of-range
   month or day is discarded and the default kept, with no flag and no error. `2021-13-40` is
   indistinguishable by value from a masked `2021-XX-XX`.
3. **`:144` — `min(day, 28 if month == 2 else 30)` fires in every month**, so 31 January returns as
   30 January and 29 February of a leap year is unreachable. `r0.parse_calendar_date`, which uses
   `strptime`, disagrees on exactly those days: three parsers, two answers for one cell.
4. **`:123` — `'.'` is normalised to `'-'`** after `float()` has claimed every plain decimal year, so
   a decimal year just outside the gate is re-read as a date rather than rejected: `'2100.5'` →
   2100.367, not NaN.
5. **`:106` — a year outside [1800, 2100] returns NaN indistinguishably** from a string no rule could
   read. (The port separates `out_of_range` from `unparsed` without changing the value, because a
   reviewable page must be able to say "your date is fine, the gate rejected it".)
6. **`:92-93` — the non-calendar path accepts `+Infinity`** (because `float('inf') >= 0.0`) and
   rejects a negative real and a literal `'nan'` by the same comparison, without falling through to
   the embedded-number search.
7. **`:218-239` — three pattern defects that lose real data**, measured on the shipped
   `examples/H1N1_2009_pandemic.fasta` (5 of 100 headers undated): the calendar delimiter class
   `[|/_\s]` excludes `-`, so `sample-2021-05-15` is undated; pattern 2 demands `\d{2,4}` decimals,
   so `|2009.4` and `|2009.8` do not match; and `re.search` offers only the **first** match, so an
   isolate number shaped `\d{4}\.\d{2}` shadows the real decimal year and, once it fails the gate,
   pattern 4's `$` anchor leaves the header undated. A "union" fix that scans all matches and widens
   the decimal to one place is an *improvement during a port* and belongs upstream, not here.
8. **`:323` — the header fallback is guarded by `len(dates) == 0`**, so a table covering 80 % of the
   taxa leaves the other 20 % undated, and `parse_temporal_metadata` returns a dict that does not
   mention them; they are dropped downstream in silence. `dating.py:481-483` falls back per taxon.
9. **`:170-186` — the Auspice walk never receives `time_units`**, so a build on a generations axis is
   gated to [1800, 2100] and returns an empty map. Same for `dating._parse_timestamp_flexible`
   (`:375`).
10. **`:164-165`, `:189` — an Auspice tip with no `name` is skipped without a word**, a name seen
    twice overwrites because the walk writes into a dict, and there is **no bare-scalar `year`
    branch** to match the bare-scalar `num_date` and `date` branches. The asymmetry looks like an
    oversight; it is replicated verbatim, with a test asserting the absence.

**`hyphaeon/dating.py`**

11. **`:330-332` — the hard-coded archival 1959 anchor.**
    `if 'Z59' in name or 'ZR59' in name or '1959' in name: return 1959.5`, before any pattern: an
    unbounded substring test on the whole header. `A/Kinshasa/1959-03-04` loses the date written in
    it; `A/Brisbane/1959/2019` becomes 1959.5; `seq_11959_2020` becomes 1959.5 because 1959 occurs
    inside 11959; an accession like `AZ59012` is dated to the archival isolate. Ported opt-in.
    **Measured and load-bearing for the ship decision:** on `examples/korber_env_gp160.fasta` the
    anchor changes **zero** rows, because the Korber rule reads `Z59ZR.ZHU` as 1959.5 anyway — which
    is what makes shipping it off safe. Upstream fix: bound the test (`^Z(R)?59` or whole-token) and
    move the calibration into the example's own metadata.
12. **`:344`, `:351` — the two-digit year pivot is hard-coded at 30**, so 2030 onward reads as 1930,
    and both rules add a flat **+0.5 that is invented, not read**. On a 40-year HIV tree that
    half-year convention is worth months of clock rate.
13. **`:355`, `:360` — `(?:WPI|wpi)` and `(?:DPI|dpi)` match neither `Wpi` nor `wPI`**, while the
    non-calendar unit patterns are `re.IGNORECASE` throughout. Worse, both return an elapsed time
    **raw onto the same axis a decimal year is on**, and nothing downstream distinguishes 16 (weeks)
    from 1986.5 (a year).
14. **`:476-479` — `m.group(1)` is unguarded**, so a `--date-regex` with no capturing group raises
    `IndexError` and the CLI dies with a traceback on the reader's first attempt at their own header
    convention.
15. **`:445-446` vs `temporal.py:274-277` — the same file is read two ways in one release.**
    `temporal` sniffs the delimiter, `dating` decides by suffix and reads `.txt` as TAB-separated; a
    tab-separated `.csv` under `dating`'s reading yields one column, whereupon the strain and date
    columns are the same column and every row dates to garbage. And `dtype` inference is on in
    `temporal`, off in `dating`: an identifier column of numeric accessions with one blank cell
    becomes float64, and `str(v).strip()` yields `'402124.0'` and `'nan'`, matching zero taxa with no
    error anywhere.
16. **`:463-464` vs `temporal.py:312` — when no date column is found**, `temporal` produces no dates
    at all, `dating` guesses `df.columns[1]`. `columns[1]` of a `taxon,location,date` table is the
    country, and a whole dataset dated from country codes is a plausible wrong answer.
17. **Explicit `--strain-col` / `--date-col` naming a column that does not exist is silently
    ignored** (`col is None or col not in df.columns`) and discovery runs instead.

**`phylotree` 2.6.0** (a dependency, not the engine)

18. **New, found by the oracle test: `reroot` loses one branch when the midpoint edge is not a direct
    child of the stored root.** Both implementations pick the same edge and breakpoint, but on
    `(((t1:0.02,t2:0.031):0.014,(t3:0.007,t4:0.05):0.022):0.011,…)` every tip on the far side comes
    back exactly 0.011 short — the length of the branch between the old root and the intervening node
    (`src/rooting.js:126-128`, the `__reroot_top_clade` / uninitialised `stashed_bl` path).
    phylotree's own two extreme tips then sum to 0.127 against the 0.138 its own `computeMidpoint`
    measured, so it contradicts itself. The invariant that settles it without a second opinion — at a
    true midpoint the two extreme tips are equidistant and sum to the longest path — is asserted
    directly, and the runtime's walk satisfies it.
19. Four previously surveyed defects, all confirmed and pinned: the constructor silently sets every
    branch to 1 and only `console.warn`s (`src/main.js:186-192`); `rootToTip` throws a **bare
    string**, so a `catch` must not touch `.message`; `fitRootToTip` reads `node.data.rtta`, which
    `rootToTip` never sets; and it considers rootings at tips only, selecting by maximum R² with no
    causality constraint, so it can date the ancestor after some of the samples. None is on a
    production path.

**A specification, not a source:** the root-to-tip survey's own claim-2 tolerance is wrong and cannot
hold. Its bound — `mu` within 3·`se_mu`, with 3·`se_mu`/`mu` < 0.20 — was derived from independent
Poisson noise, and root-to-tip residuals are not independent, because two tips sharing a deep branch
share every substitution drawn on it. Measured on a seeded synthetic: the rate lands 35.4 % from
truth, 8.38 of the fit's own `se_mu`, while the estimator is unbiased to 1e-12 on the noise-free
predictor. Taken as a copy rule rather than a code change; a test asserts the deviation exceeds three
standard errors so the fact cannot quietly go away.

## 6. Deferred, and the decisions now open

### Deferred to the phases that port the analyses

- **Both time-aware analyses.** The page ingests dates, shows what it understood, and says whether
  they carry a clock signal. It runs nothing; section 3 says so in the present tense, per
  `DESIGN.md §5`. The ready gate unlocks two downloads and a stored flag, not a run.
- **The tree-free clock preview.** Offered only where the upload carries a tree with usable branch
  lengths; the tree-free majority gets one sentence. The reference's tree-free divergence is TN93
  distance to a time-decay weighted consensus (`dating.py:623-700`), not root-to-tip, and computing
  it here would mean importing the pipeline and a worker into a route whose whole claim is that it
  loads no model.
- **`prepareRun()`'s optional `options.dates` hook** (ingestion spec §5.6). Specified and
  deliberately not built: `prepareRun` keeps its exact signature and its exact `preprocessing` block
  this phase, so every existing record, test and download stays byte-identical.
  `alignDatesToRun(ingest, prep)` is the read-only seam meanwhile; `datesVector(ingest, taxa)` is the
  `Float64Array` a regression consumes; `TimeSetRecord.id` is what a dating record will reference as
  `timeSetId`.
- **The reference-*dispatcher* fixture replays** the test survey §2.1 wanted
  (`parse_temporal_metadata`, `parse_dates_from_auspice_json`, `parse_sample_dates`). Engine-side
  files, and the engine's `hyphaeon/` was not to be touched. The suite instead pins the same
  behaviours against the reference *source* — the candidate lists lifted from the `.py` at test time
  — and against three shipped examples at measured values. `load_date_reference` already lifts by
  name, so adding them is a local change.
- **BEAST XML input** (`dating.py:428-436`): detected, refused by name with
  `DATES_BEAST_XML_UNSUPPORTED` quoting the line it is not implementing, not parsed.
- **MCP and server surfaces** for date ingestion. The layer is already surface-agnostic — it takes
  text and opens nothing, which is asserted — so mounting it is the phase that has an analysis to
  run. A `dates` comparator and a `parity/node-dates` surface wait on the same thing: there is no
  analysis output to compare yet.
- **Re-rooting as a reader action**, and the third (best-R²) rooting of the robustness check.
- **Editing a date in the table** — no design pattern, and a hand-edited date needs its own Source
  value.
- **A dated gallery example.** `korber_env_gp160.fasta` and the H5N1 pair live on the engine branch
  this worktree links, not on the pinned `ENGINE_REF`, so shipping one means bumping the ref or
  inventing data.
- **The union parser contract** the parsers survey proposed (`DATE_DIALECTS`, `alternatives`,
  `precision`, per-rule `matchIndex`, opt-in slash-dmy/mdy and ungated-numeric rules) was **not**
  built: its two departures from a literal port are exactly the "improve during a port" the house
  rules forbid. The landed 24-export surface is the contract, and the ingestion and web specs were
  written against it.

### Open decisions

1. **Which `handoff.ts` survives** — `main`'s or this branch's — and who resolves the four merge
   conflicts. No suite has run on a merged tree.
2. **When `ENGINE_REF` moves off `phase-4b`**, and whether the engine tags `feat/date-parsers` first.
   Until it moves, CI proves nothing about this phase and the positive proof is a manual
   `workflow_dispatch`.
3. **Whether `clockRegression.js` (and `rootToTip.js`) belong in the library** — decide *before*
   phase 3 ports `run_ols_dating`, or the app carries two estimators nobody may reconcile.

   refuse and make the reader choose. Related: whether `DATES_MIXED_SCALE` should block the ready
   gate.
5. **Whether the ingest should warn whenever `undated > 0`**, rather than only below 90 % coverage,
   now that `mcp/` and `server/` will consume the warning list as the whole message.
6. **What `/time` does about `se_mu`** beyond copy, given that it is understated by roughly a factor
   of eight.
7. **Rewriting the three engine commit messages** that carry AI attribution, before the branch is
   shared.
